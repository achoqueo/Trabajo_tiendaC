# Guia de Contribucion para el Equipo

1. **Creacion de Issues:** Toda funcionalidad debe iniciar con una Issue asignada en GitLab.
2. **Estrategia de Ramas:** Crear ramas cortas partiendo de `main` o `develop`:
   `feature/<nombre>` (Ejemplo: `feature/Diana`).
3. **Commits Semanticos Obligatorios:**
   - `feat(clientes): [TK-005] agregar validaciones para registro de cliente`
   - `test(clientes): [TK-005] anadir pruebas unitarias para validacion y duplicidad`
4. **Merge Request (MR):** Ningun cambio se integra a la rama principal sin abrir un MR y recibir la aprobacion (Code Review) de al menos 1 companero de equipo.
